# HunarLens: Skills-Gap Extension Plan

Put this file at `docs/SKILLS_GAP_PLAN.md`. It extends `AGENTS.md` and `docs/IMPLEMENTATION_PLAN.md`; where they conflict on skills-gap work, this file wins. Work on a git branch (`git switch -c skills-gap`) and merge to `main` only after Gate S5, because Streamlit Cloud deploys `main`.

## 0. Definition (use these exact words in the report, notebook and app)

"Skills gap, as measurable from the LFS: the difference in education and vocational-training attainment between unemployed and employed youth, the education mismatch of employed youth relative to the occupations they hold, and what happens to youth at each education level in the labour market. Education and training are proxies for skills. Vacancies and employer demand are not measured in the LFS; employer surveys (NAVTTC/NSIS) are cited as context only."

## 1. Guardrails (never break)

1. The frozen model, `models/*`, `config.FEATURES`, the prediction/validation logic, the sealed test results and all existing tests stay unchanged. Confirm the model SHA-256 at the end of every stage.
2. Occupation, industry, wages, job-search and reasons variables are labour-market variables. They are used ONLY in `scripts/09_*.py`, `src/hunarlens/skills.py` and their tests, never as model inputs.
3. Descriptive estimates describe the population, so use survey weights, and always show the unweighted n. Model-based analysis uses the VALIDATION split only and is unweighted.
4. Confidence intervals: PSU-cluster bootstrap (resample PSU = PCode + EBCode with replacement, 1,000 repeats, seed 42; note it ignores stratification). Never publish a PSU id.
5. Suppress any cell with unweighted n < 30. Flag groups with fewer than 50 observations in the relevant group as "unreliable".
6. Association-only wording. Never say training or education "causes" outcomes, and never imply individuals lack skills. Say "skills proxies".
7. Raw/person-level data is never committed. Only aggregated tables go to git.
8. Everything shown must come from `reports/tables/skills_*.csv` (generated by code), and a test must fail if the app, report or docs contain a number that does not match.
9. Data variables: inspect the real file, quote real names and codes, and test questionnaire-vs-Stata-label mismatches empirically (as was done for S5C5). Never invent variable names.
10. Stop at gates and print a STAGE REPORT.

## 2. Design decisions (change only with team approval)

| Topic | Decision |
|---|---|
| Population | Persons aged 15-24. Lenses 1-4 use labour-force youth (employed or unemployed, same label as the model). NEET uses all youth 15-24. |
| Education bands | The same five bands as Stage 4: no formal; primary or middle; matric; intermediate; degree or above. Print the code-to-band mapping. |
| Occupation grouping | ISCO-08-based 1-digit major groups (verify from the coding scheme), with armed forces excluded. Use 2-digit only if cells are large enough. |
| Mismatch, primary (statistical, ILO "realised matches") | For each occupation group, the mode of education band among employed workers = the expected level. Above the mode = over-educated; below = under-educated; equal = matched. |
| Norm population (robustness) | Primary: all employed persons aged 15+. Sensitivity A: employed aged 25-44. Sensitivity B: employed youth only. Report all three. |
| Mismatch, sensitivity (normative) | ISCO-08 skill levels by major group mapped to education bands (level 1 -> up to primary; level 2 -> middle/matric/intermediate; levels 3-4 -> degree or above). Needs human approval at Gate S1. |
| Headline view | For each education band, stacked shares of labour-force youth: employed matched, employed over-educated, employed under-educated, unemployed. |
| Weights | The LFS weight variable, with the unweighted n beside every estimate. |
| Training | `has_training` yes/no (ever or current) only; training TYPE stays excluded unless Annex C labels are verified. |
| External evidence | NAVTTC/NSIS skills-gap reports cited as context only (survey year, scope and method stated). No numbers merged into our tables. |

## 4. Stages

### S0: Setup (0.5 hour)
- Create the branch and add rule R15 to AGENTS.md: "Skills-gap work follows docs/SKILLS_GAP_PLAN.md; labour-market variables are used only in scripts/09_* and src/hunarlens/skills.py, never in model inputs."
- Add placeholders: `src/hunarlens/skills.py`, `tests/test_skills_*.py`.
- Acceptance: pytest passes; the model hash is unchanged.

### S1: Variable audit (no analysis)
Write `docs/skills_gap_data_audit.md`: for each item, exact variable names, questionnaire wording, codes, skip logic, classification (version and code length), missing codes, weighted and unweighted counts for ages 15-24:
1. Occupation and industry of the main job.
2. Employment status and sector variables.
3. Training (ever or current; source) and the Annex C labels for training type.
4. Field of study for degree holders, if recorded.
5. For unemployed youth: previous occupation or industry, type of work sought, reasons for not finding work, search methods, duration of unemployment.
6. NEET components for all youth 15-24, including outside the labour force.
7. Survey weight, strata and PSU variables.
Report every mismatch between questionnaire and Stata labels and test the important ones empirically. Propose the education band mapping, the occupation grouping, the skill-level mapping, and the analyses the data supports with employed-youth group sizes by occupation group, sex and area.
**GATE S1 (humans, ~1-2 hours):** check five variables against the coding scheme PDF; approve the occupation grouping, mismatch definitions and the list of analyses; decide which optional lenses are included. Record in `docs/DECISIONS.md`.

### S2: Skills dataset and reproduction check
- `scripts/09_skills_gap.py --build`: de-identified person-level table in `data/interim/` (git-ignored) with age, sex, area, province, education band, has_training, enrolment, labour-force status, occupation group, industry, weight, PSU id (internal only). Drop names, addresses and any ID. Row waterfall in `reports/tables/skills_row_waterfall.csv`.
- **Reproduction test (like the label gate):** compute weighted employment shares by occupation major group and by industry for ALL employed persons, and weighted education distribution, and compare with PBS published tables from the Annual Report or the statistical tables (URLs verified, listed in `data/raw/MANIFEST.json` or reachable). Save `skills_reproduction.csv` (indicator, our_value, pbs_value, source_url, difference, status). Accept within 0.5 percentage points. If a value does not reproduce, show crosstabs and propose fixes; never tune just to hit a number.
**GATE S2:** the reproduction passes or discrepancies are resolved by the team.

### S3: Analyses (weighted, with cluster-bootstrap intervals)
1. **Attainment gap** (`skills_attainment_gap.csv`): shares of employed vs unemployed youth in each education band and in has_training, differences in percentage points (unemployed minus employed), overall and by sex, area, sex x area and province.
2. **Absorption** (`skills_education_occupation_matrix.csv`): for employed youth, the distribution of occupation groups within each education band, and the share of degree-holding employed youth in ISCO major groups 1-3 vs elsewhere.
3. **Mismatch** (`skills_mismatch.csv`, `skills_mismatch_sensitivity.csv`): shares matched, over- and under-educated among employed youth, overall and by sex, area, province and age band (15-19, 20-24), for the primary norm and both sensitivities and the normative variant. Print the mode table per occupation group.
4. **Outcomes by education** (`skills_outcomes_by_education.csv`): for each education band, shares of labour-force youth who are employed matched, over-educated, under-educated, or unemployed (they sum to 100%). Also the unemployment rate by education x has_training (suppress n < 30).
5. **Training by occupation** (`skills_training_by_occupation.csv`): share with training in each occupation group, and unemployment by training within education band.
6. **NEET** (`skills_neet.csv`, P1): NEET rate for youth 15-24 by education, sex, area and province; define it from the audited variables and say so.
7. **Unemployed barriers** (P1, only if the survey records them): reasons for not finding work, type of work sought, previous occupation; compare the type of work sought with where employed youth with the same education actually work.
8. **Model-based shift** (`skills_model_shift.csv`, P1): VALIDATION split only, the frozen pipeline through the app's `build_input` and `validate_inputs`. For each youth compute the predicted probability for the actual profile, for education one band higher where valid, and for training set to yes. Skip rare or invalid combinations. Report mean differences (percentage points) by sex x area and by education band, with household-grouped bootstrap intervals. Label: "model-estimated difference between profiles, not a causal effect."
**GATE S3:** the team reviews tables, interval widths, suppressed cells and unreliable flags.

### S4: Notebook, methods and findings
`notebooks/07_skills_gap.ipynb` (lifecycle narrative), `docs/skills_gap_methods.md` (definitions, formulas, mode method, norms, weights, bootstrap, suppression, limitations) and `docs/skills_gap_findings.md` in plain language with association-only wording. Limitations to state: education proxies skills; no vacancy or demand data; occupation measured only for the employed; cohort differences (younger workers are more educated, so norms from all ages may overstate youth over-education; hence the sensitivity norms); labour-force-only sample for lenses 1-5; training type excluded; weights used here but not in the model; small groups unreliable.
**GATE S4:** read the findings for any causal wording, any claim about individuals, or any number that does not match a table.

### S5: Dashboard page
Add a "Skills gap" page to the dashboard (`app/prototype.*` and the data builder), between Overview and Profile explorer; desktop sidebar item and mobile bottom nav item. Use the existing design tokens, cards, tags ("Official survey" vs "Our analysis" labels), `.metric-row`, `.card` and chart patterns. Content, all from `data.skills.*` loaded from the generated tables:
- Headline outcomes by education band (stacked bars, text labels, not colour alone).
- Attainment gap chart with intervals and a filter (sex, area, province, age band) using precomputed combinations only.
- Education-to-occupation heat table (accessible table, not an image).
- Mismatch card with a norm selector (primary / 25-44 / youth-only / normative) and the matching note.
- Training card and NEET card (if built).
- A "How to read this page" card with the definition in Section 0 and the limitations.
Rules: nothing hard-coded; tests fail on typed statistics; fallback classic view gets the same tables; accessibility (labels, focus rings, reduced motion, 44px targets); no new runtime dependency.
**GATE S5:** run the app locally and on a phone; a teammate who did not build it uses the page; then merge to `main`, redeploy, and check the public URL.

### S6: Report and viva
- Add a "Skills-gap analysis" subsection to Methods (half page) and Results (one figure, one table, about half a page); shorten EDA text to stay at 3-4 pages. Use the Section 0 definition. Add limitations and references (ILOSTAT mismatch methodology; the ETF skills-mismatch measurement guidance; NAVTTC/NSIS skills-gap reports for context with survey year stated; PBS LFS 2024-25).

- Update the README (new page, new script, how to reproduce `scripts/09_skills_gap.py`).

### S7: Final checks
Full pytest, fresh runtime-only clone, tracked-file check, static scan for forbidden strings and untracked numbers, screenshots at 1440, 1024 and 390 widths, model SHA-256 unchanged, tag `v1.1-skills-gap`.

## 5. Risks

| Risk | Mitigation |
|---|---|
| Occupation codes or labels mismatch the questionnaire | Audit and empirical tests at S1; never trust labels alone |
| Estimates do not reproduce PBS tables | Gate S2; fix definitions before analysing |
| Small cells | Suppress n < 30; flag < 50; use broader bands |
| Over-education overstated by cohort effects | Three norm populations and the normative variant |
| Readers infer causation | Wording rules, tests scanning the docs and the app |
| Breaking the live app | Work on a branch; merge only after Gate S5 |
| Time spent on optional lenses | P1 lenses after the core four; NEET and barriers only if the variables exist |
